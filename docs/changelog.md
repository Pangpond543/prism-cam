# Prism Cam — changelog (newest first)

Format: `YYYY-MM-DD — what changed — why`. Add a line after every fix/feature.

- 2026-11-18 — **v1.0.1** (speed panel / light mode / GPU conversion, 30–60 fps, and the fixes below).
- 2026-11-18 — Fixes + polish from user report: (1) Library tiles flickered on hover — the tile lifted 2 px off a pointer resting on its bottom edge, dropped back, lifted again; a 4 px `::after` strip keeps the hover zone (same for `.pick .eg-b .at-clip .qe .at-tog`), and `renderLib` skips rebuilding identical HTML (every studio refresh used to rebuild the grid under the pointer). (2) Ctrl+Z "sometimes doesn't stick" — undo picked the zone under the mouse, so with the pointer over another panel it undid nothing / an older change; now one Ctrl+Z always undoes the newest change of any zone (toast names it). A text box you typed in no longer keeps Ctrl+Z after you click elsewhere (it is blurred on any outside press — the stage / timeline take the pointer without moving the focus). (3) Stage clicks: a press that moves < 4 px is a click, not a nudge; dragging on the selected layer moves it even under other layers (a plain click there still selects the top one); Alt+click = the layer below; small layers hit as ≥ 24 screen px; handles hit 28 px; move cursor over layers. (4) Position & size: "Size" slider (100 % = fits the screen / area, never stretches, scales every selected layer), − / + 10 %, "Actual size", "Fix stretch" (restore the media's own aspect, same area); edge handles of pictures / video keep the aspect too (Shift = stretch, Alt = crop as before). (5) Corner placement chips: emoji arrows → picture-in-picture icons (`pipTl/Tr/Bl/Br`). (6) Every `<select>` in the app is drawn as a glass dropdown (`select.js`: native select stays hidden as source of truth, MutationObserver picks up new ones, keyboard ↑↓ Enter Esc + type-to-jump, opens upward near the bottom). — user report with screenshots.

- 2026-11-18 — 30 / 60 fps picker in the status bar (next to the resolution; saved in the project as `out.fps`, default 30). 60 = the scene, effects, screen capture and recordings run at 60; cameras are asked for 60 (`camRate`) and switched live with `applyConstraints`; a camera that gives less shows "กล้องนี้ได้แค่ N fps". The virtual camera stays at 30 (Discord's limit; the DLL is unchanged): a 60 fps project sends every other frame. Auto quality first drops 60 → 30 (`perf.cap30`) before lowering the resolution, and goes back to 60 when there is room. AI background keeps ~15 masks/s at either rate. Recording now uses `captureStream(0)` + `requestFrame()` after each draw — the automatic capture lost ~15 % of the frames at 60 (measured 50–52 fps with VP9 / VP8 / H.264 alike); the frame clock follows a fixed schedule so timer jitter adds or drops no frames. Measured: recording 60.1 fps at 60, 29.7 at 30; virtual camera 30–31 fps. The user's USB Camera only does 30 → warning shown. — user request.

- 2026-11-18 — Speed for weak PCs (a friend's Ryzen 5 5500GT with integrated graphics stuttered in Discord at 74 % CPU). New `perf.js` + `perfui.js`: (1) the scene canvas is now a GPU canvas and a WebGL2 pass converts it straight to NV12 (`nv12`, async read-back through 2 pixel-pack buffers + fences, one frame late) → `vcam_frame` with `x-fmt: nv12` = plain memcpy in Rust (`push_nv12`); the RGBA path stays as fallback and now converts on up to 4 threads. (2) Light mode (`html.lite`): draws at 75 %, the converter scales back to full size, AI background every 3rd frame, hand tracking ≤ 15/s, no backdrop blur, background stands still; turns on by itself on the first start if WebGL reports integrated graphics. (3) Automatic quality: render scale 100 → 75 → 50 % when the PC falls behind (fps < 85 %, frame work > 80 % of the budget or whole-PC CPU > 92 % for 3 s), back up after 10 s of room; ignores the first 10 s and 5 s after the camera starts. (4) Speed panel (click the fps number): switches + fps drawn / sent, resolution, whole-PC CPU (`perf_cpu`, GetSystemTimes), ms per part, "copy details" for chat. Also: frame ticks that pile up on a slow PC are dropped instead of drawn late; hand tracking capped at ~30/s. Measured on the user's PC (i3-12100F + RX 6600, camera + text, 720p30 to the virtual camera, 12 s windows, all Prism processes): old 27.5–30.9 % → new 23.8 % → light mode 20.2–22.6 %; drawing 2.5 → 0.3 ms/frame; 30 fps reach the camera. 3 min run on the GPU canvas: 0 display-driver events. Not measured on an integrated-GPU PC. — user request (options picked: light mode, GPU conversion, auto quality, speed panel).

- 2026-11-18 — First public release v1.0.0 on GitHub (Pangpond543/prism-cam): `tools/release.sh` builds `Prism-Cam-<ver>-Setup.exe` (own NSIS script `tools/installer.nsi`, per-user, no admin) and `-Portable.zip`. In-app updater for packaged copies now downloads the matching release file (`update::apply_release`: installed → new Setup.exe run with `/S /RELAUNCH` on restart; portable → zip unpacked over the folder, files in use renamed to `*.old`, cleaned on next start). Source checkouts still rebuild with cargo. Basic hand poses taught by the author (built-in poses + “no pose” + heart / pray, no custom poses) ship in `app/renderer/data/default-hands.json` and fill the profile on first start; hand-profile menu → “use the default basic poses”. Translation audit: ~220 Thai strings of the Hand tab / teaching / F9 / PC control had no English → all added (`lang-en.js`); macro placeholder example translated. README rewritten (TH + EN, F9 tip). — user request.


- 2026-11-18 — Animation area = one object, like a video: moving / resizing / turning the box (handles, group box, wheel, numbers, "fill screen") carries everything inside — positions, sizes, turn, radius / border and their keyframes (`syncAreas` / `carryKids`, box remembered in non-saved `_f`). Alt while dragging an area handle = box only; "fit box to contents" (area panel + right-click). In animation mode the contents scale with the area's animated width / height too (`areaKx/areaKy`, `hooks.rest` = the area's box before the running edit, so the drag previews live). Editing inside an area: a click outside its box steps back out (`leaveAreaAt`) — marquee / clicks no longer get stuck on the inside layers. — user request.
- 2026-11-18 — Fix: resizing several selected layers warped in animation mode — the group remembered un-animated sizes/turns before `hooks.begin` stood the layers where the animation shows them (`groupItems` now calls begin first). Areas in the group now scale their contents. — user report.
- 2026-11-18 — Fix: switching output portrait ↔ landscape made everything smaller each time (sizes × min(kx, ky)). Now `resizeOut`: positions follow the canvas, sizes × √(kx·ky) (round trip is lossless), layers that filled the canvas fill the new one (media re-cropped, not squashed), keyframes and area contents follow; toast with Undo. — user report.

- 2026-11-16 — Fix: pressing K / the add-key button / the "+" menu on a layer with no keyframes stored "no value" (X Y shown as NaN) and the picture jumped to the top-left corner. Cause: the new row was created before the layer's value was read (`dispV` found an empty row). `dispV` now falls back to the layer's own value, `setKey` refuses empty values, `fixClip` drops broken keys from old saves. — user report with screenshots.
